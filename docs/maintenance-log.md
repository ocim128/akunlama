# Repository maintenance log

Read this log before choosing maintenance work. Record the demonstrated issue, bounded change, verification, and useful follow-ups; keep the newest entry first.

## 2026-10-02 - Distinguish failed inbox checks from empty results

- **Evidence:** Failed initial inbox requests displayed the empty-inbox view, and failed refreshes advanced "Last checked" despite receiving no messages. Six new regression cases failed before the fix, including network failures, HTTP 429/503, and preservation of the last successful check time.
- **Change:** Show an accessible error with a retry button; preserve previously loaded messages and the last successful check time. Clear errors after successful checks or inbox navigation, and prevent aborted requests from changing the next inbox's state. Added seven unit cases and a browser test using a local HTTP server to verify a real 503 response followed by successful retry. Documented the behavior in troubleshooting. Preserved all earlier maintenance work.
- **Checks:** All 126 UI unit tests passed; the unchanged Worker suite passed all 218 tests. Both package type checks, the UI production build, and `git diff --check` passed. All 60 affected inbox E2E cases passed across Chromium, Firefox, WebKit, Mobile Chrome, and Mobile Safari (`PLAYWRIGHT_PORT=5184`, `node node_modules/@playwright/test/cli.js test tests/e2e/inbox.spec.ts tests/e2e/inbox-errors.spec.ts --workers=2 --reporter=list` from `ui`). No tests in these runs were skipped. Other browser suites, live email delivery, and deployment were not run.
- **Follow-ups:** Ingestion failure handling conflicts with an older plan that explicitly avoids throwing processing errors; confirm Cloudflare's actual delivery/retry behavior before changing it. Existing E2E API route mocks were observed to miss requests in WebKit; the new regression uses a local server, and the older mocks merit a separate review.

## 2026-10-02 - Render plain-text emails literally

- **Evidence:** The UI loads message bodies through `/api/getHtml`. Its fallback inserted `body_text` into HTML without escaping and sniffed it for HTML/quoted-printable content, although ingestion already separates and decodes MIME bodies. Regression fixtures returned a live tracking `<img>`, interpreted quoted style/link markup, and corrupted Unicode when literal `=3D` appeared.
- **Change:** Escape `&`, `<`, and `>` in the plain-text fallback; remove HTML sniffing and repeated transfer decoding. Keep existing line-break display, HTML-body preference, sandbox headers, link handling, and caching. Added eight regression cases and documented the rendering contract. Preserved all prior delivery-fix work.
- **Checks:** Baseline: 210 Worker tests and 119 UI tests passed. After the fix: all 218 Worker tests passed, including plain-text output, Unicode, line breaks, HTML alternatives, and ETag revalidation. Both package type checks and `git diff --check` passed. No unit tests were skipped. Browser E2E and live email delivery were not run; the response behavior is covered by route tests using the existing HTMLRewriter test double.
- **Limits:** Historical HTML stored only in `body_text` now displays literally; the current ingestion contract stores HTML in `body_html`. No schema migration or deployment was performed. Applies to both domains through the shared Worker code.
- **Follow-ups:** The plain-text issue noted in the previous entry is addressed. Ingestion still logs and swallows processing failures; investigate delivery-failure behavior separately. The older backlog and developer-guide discrepancies remain.

## 2026-10-02 - Deliver inbound mail to the SMTP envelope inbox

- **Evidence:** `handleEmail` preferred the MIME `To` header over Cloudflare's `message.to`. New handler tests failed in 14 of 18 cases before the fix: Bcc/Cc, undisclosed recipients, multiple recipients, conflicting headers, and blocked-mail registry attribution failed on both supported domains. [Cloudflare's contract](https://developers.cloudflare.com/email-service/api/route-emails/email-handler/) defines `message.to` as the envelope RCPT TO.
- **Change:** Use the trimmed, lowercase envelope recipient for `emails` and `recipient_registry`. Added 18 regression cases using the real MIME parser, filter, and registry service with a mocked D1 binding. Documented the inbound type and API recipient semantics. No schema migration is needed.
- **Checks:** Baseline UI unit tests: 119 passed; baseline Worker tests: 192 passed. After the fix, Worker tests: 210 passed, including all 18 new cases. Worker and UI type checks, UI production build, and `git diff --check` passed. No unit tests were skipped. Browser E2E and live SMTP delivery were not run; this change is confined to inbound Worker recipient selection and was verified with raw MIME fixtures.
- **Limits:** Applies to newly received messages once deployed to each domain's Worker. Existing rows cannot be reliably reassigned because their original envelope recipient was not retained. No deployment was performed.
- **Follow-ups:** Review ingestion failures that are logged and swallowed in `handleEmail`, and the legacy HTML endpoint's interpretation of plain-text bodies as markup. These were observed while inspecting the repository and remain separate work. Older backlog plans and the developer guide describe test/configuration states that differ from the current code; verify them before choosing future work.
